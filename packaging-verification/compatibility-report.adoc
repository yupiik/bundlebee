== JSON implementation caveat

Helm's compatibility adapter uses a generated single-Object-field model to select Fusion's dynamic JSON codec and removes that fixed envelope from the mapper's output.
This is a localized, tested workaround: Fusion's direct BigDecimal codec serializes strings, while its Object codec preserves numeric values, and homogeneous-map specialization can select an inappropriate codec for heterogeneous nested collections.
Removing the envelope and directly invoking `JsonMapper.toString` reproduced both a numeric-wire-type regression and malformed nested JSON.
There is no hand-written parser or custom JSON codec in the adapter.
Exact-formatting, escaping, numeric, null and heterogeneous-collection tests cover this boundary.
A public Fusion API for explicitly requesting dynamic-root serialization would allow this workaround to be removed without changing the intentional typed BigDecimal contract.

== Remaining validation and compatibility limitations

* The state Secret reader correction and its safety policy are approved intentional version-1 bugfixes, not strict legacy behavioral parity.

* A full all-command/all-option behavioral matrix, including every destructive/network command and every historical extension, is not complete.

* Configuration-key availability and Maven descriptor parity do not independently prove conversion/behavior parity for every possible input.
* The full legacy corpus has not yet been driven through both CLI and Maven frontends with identical local HTTP request-sequence assertions.
* Public Java extension APIs changed with the approved CDI/JSON migration; the earlier Lombok API comparison only established equivalence immediately before/after Lombok removal, not binary compatibility with 1.x.
* JSR223 `lookupByName` was explicitly removed as part of the accepted extension migration; recipes must use `lookupByType` with a registered Fusion bean type instead of CDI aliases.
* Snapshot/release repository routing, immutable dependency availability, real release signing credentials and actual Central acceptance remain unverified.
* Snapshot routing now targets Sonatype's current snapshot endpoint, and the Krew archive URI is explicitly overridable for snapshot rehearsals; actual hosted availability, namespace enablement and publishing credentials remain external prerequisites.
* Production signing, hosted Krew installation and coverage of every operating system/architecture were not tested; local signature/archive verification and the selected native builds do not establish those contracts.
* Collection serialization timing remains too variable to claim performance parity.

These items must not be reclassified as successful merely because the reactor tests or release rehearsal pass.
